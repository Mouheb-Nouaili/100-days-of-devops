# Day 003 : Disable Direct Root SSH Login

Security audit asked to block direct root login on all app servers of the Stratos Datacenter.

Connect with the named user and become root:

```bash
ssh tony@stapp01
sudo su -
```

Edit the config and set the line, uncommented:

```bash
nano /etc/ssh/sshd_config
```

```
PermitRootLogin no
```

sshd reads its config only at startup, so nothing changes until it restarts. The current session survives it, only new connections are affected:

```bash
systemctl restart sshd
```

Repeated on stapp01 (tony), stapp02 (steve), stapp03 (banner).

Now `ssh root@stapp01` is denied, even with the right password. Root access is not removed, it just has to be reached through a named user, `sudo su -` still works.

**Why:** with a shared root password the log only says root connected, nobody knows which person it was. Going through your own account leaves the name at both steps:

```
sshd: Accepted password for tony from 10.244.13.9
sudo: tony : USER=root ; COMMAND=/bin/su -
```

> Service is `sshd` on RHEL but `ssh` on Debian and Ubuntu.
